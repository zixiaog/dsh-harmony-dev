# 架构与接入 · 鸿蒙开发台

> 读者：要二开、扩展内容域、或把插件接入别的 Harness 的人。

---

## 1. 分层

```
L5 Client 面板（client.js：__ModuleLoader__ → main + sidebar.panellist）
L4 技能层（后续：skills/*.md，M4 后续接入）
L3 工具层（index.js：harmony_search / get / build / check）
L2 服务/能力层（lib/mcp.js 官方通道、lib/check.js 静态检查、生成器）
L1 数据层（data/*.json：cards / rules / tokens / versions）
L0 内容源（content/*.yaml|json；build_data.py 产出 L1）
```

运行时**只读**本地数据；写操作仅限 `harmony_build` 返回代码文本（由调用方落盘）。

---

## 2. 目录职责

| 路径 | 职责 |
|---|---|
| `index.js` | 函数式 Host 插件：`name` / `inject` / `apply`；工具注册与生成/检索编排 |
| `lib/mcp.js` | 华为知识库 MCP 客户端：`initialize` → `tools/call`，12s 超时、60s 熔断、`mcpReset()` |
| `lib/check.js` | 静态检查：14 条规则检测器 + 迁移 + 无障碍/一多/版本/上架清单 |
| `data/` | 构建产物（cards/rules/tokens/versions + manifest），随包分发 |
| `content/` | 人类维护的源文件；构建时校验 |
| `scripts/` | `build_data.py`（构建）、`check_rules.py`（规则回归）、`test_m0.mjs`（自测）、`run_golden.mjs`（金标集） |
| `examples/` | 20 个可读 ArkTS 示例（不进构建，作为示例索引卡指向的文件） |
| `docs/` | 本目录三份文档 |

## 3. Host 插件契约（实测结论）

```js
export const name = 'harmony-dev-kit';   // 必须：缺 name 时 apply 不被调用
export const inject = ['tools'];
export function apply(ctx, config) { ... }
```

三条硬约束（详见 README 踩坑记录）：

1. **不要用 Service 类 + `import('@deepseek-ai/cordis')`**：本地目录安装是 Junction，解析不到宿主依赖。
2. **`export const Config` 不能是普通 JSON Schema**：cordis 激活时调用 `Config.validate()`，会抛错导致整插件不激活。
3. **生效方式**：`set_bundle enabled=false → true` 重新 import；只改数据不改代码不会重载（需改 index.js 或重启）。

## 4. 工具契约

| 工具 | action/入参 | 输出关键字段 |
|---|---|---|
| `harmony_search` | `query`, `domain?`, `limit?`, `targetApi?` | `data.{cards,rules,tokens,official,meta}`, `citations`, `warnings` |
| `harmony_get` | `ref`, `kind?`（auto/card/rule/token/version/official）, `from?`, `to?` | `data.{kind,item|docs}` |
| `harmony_build` | `action`（tokens/scaffold/page）, `name?`, `layout?` | `data.files[]`, `data.selfCheck` |
| `harmony_check` | `action`（review/migrate/a11y/one_multi/version/release）, `code?`/`path?`, `from?`/`to?` | `data.diagnostics[]`, `summary.verdict` |

所有工具返回**无损 JSON**（统一 `lossless()` 清洗 undefined/NaN），`output.schema` + `output.render` 必填（宿主硬要求）。

## 5. 官方知识库通道

- 端点：`https://connect-api.cloud.huawei.com/api/developerknowledge/mcp`（streamable HTTP + JSON-RPC）。
- 流程：`initialize`（协议 `2025-11-25`）→ `notifications/initialized` → `tools/call`。
- 参数（来自 `tools/list` 实测）：`{ SearchDocumentsReq: { query, topK } }`、`{ GetDocumentsByIdRequest: { names } }`。
- 输出：`resultList[]`，搜索项含 `{parent, content}`，全文项含 `{name,title,uri,content}`。
- 失败处理：超时/HTTP/协议错误 → 熔断 60s → 返回 `{ok:false}` → 工具降级本地快照并 `warnings` 说明。
- 重新激活时 `mcpReset()` 清熔断（模块在 ESM 缓存，状态不随 index.js 重载自动清）。

## 6. 数据流

```
用户 query
  → harmony_search
     ├─ 本地：cards/rules/tokens 关键词打分（中文别名扩展）
     ├─ 版本过滤：since > targetApi 的卡片排除并告警
     └─ 官方：mcpSearchDocuments（失败降级）
  → 合并结果 + citations + version 口径
```

生成流：

```
harmony_build(page)
  → 选模板（settings/list）
  → 注入 Tokens.ets 引用（screenMargin/gapLarge/Font.Title_S/Radius.card…）
  → 自查（颜色/字号/间距/圆角字面量；断点；无障碍；V2）
  → 返回 files + selfCheck
```

## 7. 扩展一个新内容域

1. `content/cards/<域>.yaml` 加卡片（遵守 schema）。
2. `scripts/build_data.py` 的 `card_files` 列表加入文件名。
3. 跑 `python scripts/build_data.py` + `node scripts/test_m0.mjs`。
4. 若需要检索别名，在 `index.js` 的 `ALIASES` / `GROUP_CN` 增加词条。
5. 更新 `docs/` 与 README 计数。

---

## 8. 接入其他 Harness

- 工具契约与本插件解耦：`harmony_*` 的输入输出都是 JSON，可包成 MCP server 供其他客户端调用。
- 数据层 `data/*.json` 可直接被检索服务消费，不依赖 cordis。
- 面板是独立的 `window.__ModuleLoader__` 模块，离开本宿主需替换 slot 注册层。

---

## 9. 升级注意

| 变更 | 影响 |
|---|---|
| `rules.yaml` 增删规则 | 同步 `rules/samples`、`data/rules.json` 重建、`harmony_check` 检测器映射 |
| `content/tokens.json` 改值 | 重新生成 `data/tokens.json`；`harmony_build` 输出随之变化；生成页需重跑自查 |
| 官方 MCP schema 变更 | `lib/mcp.js` 只改参数封装与 `pickDocs`；熔断/降级逻辑不动 |
| 宿主版本升级 | 关注 `Config.validate()`、`apply` 调用约定、`output.render` 要求（已踩过坑） |
