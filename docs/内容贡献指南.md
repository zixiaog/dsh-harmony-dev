# 内容贡献指南 · 鸿蒙开发台

> 读者：给插件写卡片、补规范、改规则的人。目标：让内容**可校验、可追溯、不漂移**。

---

## 1. 内容放在哪

```
content/
├─ tokens.json                 # 设计 token（唯一真源）
├─ versions.json               # 版本表 + apidiff
└─ cards/
   ├─ cards.yaml / components*.yaml   # 组件卡
   ├─ design*.yaml                    # 设计规范条目
   ├─ api*.yaml                       # API 卡（含 40 张 Kit 概览）
   ├─ lessons*.yaml                   # 课程
   └─ examples*.yaml                  # 示例索引
```

改完跑两条命令：

```bash
python scripts/build_data.py     # 校验 + 合并 → data/*.json
python scripts/check_rules.py    # 规则正反例回归
node scripts/test_m0.mjs         # Host 自测（含工具调用）
```

构建会拒绝：缺字段、id 重复、`sections.usage/example/pitfalls` 缺失、`state_mgmt` 非法、规则越级（见下）。

## 2. 卡片 schema

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | `comp.*` / `design.*` / `api.*` / `lesson.*` / `example.*`，全局唯一 |
| `domain` | ✅ | `component` / `design` / `api` / `engineering` / `tutorial` |
| `title` / `summary` | ✅ | 标题与一句话说明 |
| `since` | ✅ | API 起始版本，**必须来自 apidiff**；不适用写 `—` |
| `baseline` | ✅ | 核对时的事实基线，如 `6.1.1(24)` |
| `state_mgmt` | ✅ | `V1` / `V2` / `mixed`；设计/API/课程条目写 `—` |
| `sections.usage` | ✅ | 何时用、关键约束 |
| `sections.example` | ✅ | 可运行示例或正反例（代码/文本均可） |
| `sections.pitfalls` | ✅ | 常见错误，数组 |
| `sources` | 建议 | `{title, url, fetched}`；**url 为空的规则不得为 error** |
| `updated` | ✅ | 最后核对日期 |

可选：`props` / `events` / `applies_to` / `tokens` / `version_note` / `a11y` / `adapt` / `perf` / `level` / `order` / `checkpoints` / `exercise` / `file` / `topics`。

### `topics`：把一张卡拆成官方文档级主题（推荐给复杂组件）

复杂组件不要只写一段摘要，拆成可下钻主题，每条可独立阅读、带代码与官方出处：

```yaml
  topics:
    - id: list.lazy              # 必填，card 内唯一
      title: 使用懒加载（LazyForEach / NodeAdapter）
      content: |                # 必填，2~6 行讲清是什么/什么时候用/坑
        大数据量必须懒加载：ArkTS 侧用 LazyForEach + IDataSource……
      code: |                   # 可选，能复制粘贴的 ArkTS 片段
        List() { LazyForEach(this.source, ..., (item) => item.id) }
      source: "https://developer.huawei.com/consumer/cn/doc/..."  # 可选
```

- 构建会校验：topics 必须是数组、id/title/content 非空、id 不重复。
- 面板会把 topics 渲染成「主题（N）」折叠项；`harmony_search` 会检索主题正文，并在结果里返回命中的 `topics[]`。
- 主题来源优先级：**精编**（YAML 里手写，最高）→ **官方目录**（`content/topics/kits.json`，由 `enrich_kit_topics.mjs` 用官方 MCP 抓 Kit 简介页子章节生成）→ **自动整理**（`synthesize_topics()` 从属性/事件/坑等字段生成）。
- 参考实现：`comp.list`（8 个精编主题）、`kit.uidesign`（11 个精编主题，对齐官方《UI Design Kit 简介》目录）、`kit.arkui`（官方目录 5 个主题）。

### 紧凑写法（API 推荐）

```yaml
- id: api.data.preferences.has
  title: "Preferences.has"
  summary: 判断键是否存在
  since: "API 9"
  sig: "has(key: string): Promise<boolean>"
  ex: "if (await store.has('token')) { ... }"
  pit: [先 has 再 get 多一次 IO]
```

构建会把 `sig/ex/pit` 展开成 `sections.usage/example/pitfalls`，并补默认元数据（`domain: api`、`state_mgmt: —`、`baseline: 6.1.1(24)`）。

## 3. 硬规则（违反会被构建拒绝）

1. **`since` 不许手写猜测**：要么来自 `versions.json` 的 apidiff/K在版本表，要么写 `—` 并在 `version_note` 说明。当前 API 卡多数标「since 待校准」——补准确值即可去掉标注。
2. **规则越级禁止**：`severity: error` 必须有 `spec.url`；`calibrated: false` 的规则不得为 error。
3. **不允许虚构章节**：设计规范条目必须能对应官方目录（`llms/docs-ux-design.txt`）。
4. **token 缺号禁止**：间距无 `l14/l15/l24/l31`，圆角无 `level14/15/17`；引用前查 `content/tokens.json`。
5. **版本维度**：设计 token 带设备维度（手机/穿戴取值不同），不要给"一套全局色板"。

---

## 4. 写一条新卡片的步骤

1. 查官方原文（优先 `llms/docs-*.txt` 索引 → `.md` 直链；或 MCP `searchDocuments`）。
2. 选目录与 id；写 `summary`（一句话）、`sections.usage`（什么时候用/约束）。
3. 写 `sections.example`：**能复制粘贴的代码**或明确的正/反例。
4. 写 `sections.pitfalls`：至少 1 条真实坑。
5. 填 `sources`（title/url/fetched）与 `updated`。
6. 跑构建 → 自测 → 提交；CI 会跑规则回归与 schema 校验。

## 5. 审核清单（PR 前自查）

- [ ] `python scripts/build_data.py` 通过
- [ ] `node scripts/test_m0.mjs` 通过
- [ ] 新增/修改的卡片有 `sources` 且 URL 可打开
- [ ] `since` 有依据（apidiff / 版本表 / 官方页）
- [ ] 示例是 ArkTS 且只引用 token（无魔法值）
- [ ] 规则改动带正反例（`rules/samples/`）
- [ ] 不复制官方文档整段内容（只做摘要 + 链接）

---

## 6. 规则与样本

- 规则唯一真源：`rules/rules.yaml`（34 条）。
- 每条规则需 ≥3 正例 + 3 反例（当前 8 条已具备，其余在 `rules/README.md` 列为待补）。
- 改规则必须同步 `rules/samples/*.json` 并跑 `check_rules.py`。

---

## 7. 内容时效

- `updated` 超过 90 天标黄，超过 180 天强制复核。
- 官方版本升级（如 26.0.0 发布）后：先更新 `versions.json` 的 apidiff，再扫一遍受影响卡片。
